산출물 위치와 파일명은 .production/layout.md를 따른다.

프로젝트 루트의 `.production/workflow.md`가 기준이다. 현재 단계의 `## NN.`부터 다음 제목 직전까지만 읽는다. work/status.md의 진행 기록에서 1단계 통과, 3단계 시나리오 승인, 4단계 모드와 중간 확인 지점을 확인한다. 선행 단계가 미완료면 그 단계로 돌아간다. 순차 모드는 각 단계의 사용자 확인을 기다리고, 일괄은 수정 가능한 문제를 같은 단계에서 해결한다.

- 이번 프로젝트의 소스 목록에 있는 참조만 연다. 예시의 파일이 첨부되지 않았으면 필요한 원본을 묻고, 신규 제작이 승인된 인물·소품은 이 프로젝트에서 새로 만든다.
- 5단계에서 해당 인물마다 같은 인물의 세 각도 이상을 한 시트에 담는다. 원본과 새 소품 이미지를 소품별로 구분하고 Flow에서 개별 선택 가능한지 확인한다.
- 6단계에서 시나리오 순서대로 첫 콘티를 확인한 뒤, 각 후속 장면에 첫 콘티와 직전 채택 콘티, 필요한 개별 참조만 쓴다. 인물·소품·콘티 이미지 프롬프트도 한국어 검토본과 영어 제출본을 함께 작성하고 Flow에는 영어판을 제출한다. 장면별로 파일·버전·참조 대응을 기록한다. 이미지를 만들 때 컷별로 파일의 용도(소재·시작 이미지·끝 이미지·편집용 원본)를 기록한다. 시작·끝 지정에는 해당 요청이나 시나리오 구간을 적는다. 콘티 채택, 첫 장면이라는 순서, 편집용 엔딩 표지는 프레임 지정의 근거가 되지 않는다. 시작 이미지와 끝 이미지가 모두 미지정이면 Flow의 소재(Ingredients) 모드를 사용한다. 사용자 또는 승인 시나리오가 특정 이미지를 시작이나 끝으로 지정한 컷만 프레임(Frames) 모드로 만들고, 지정된 파일만 해당 위치에 넣는다.
- 7단계에서는 `storyboard_reviewer`에 독립 검수를 맡긴다. 승인 시나리오의 해당 구간과 이후 사용자가 바꾼 구도·자세·제외 컷, 규격, 현재 콘티와 참조 대응, 엔딩 소재·시간만 보낸다. 과거 대화나 제작자의 예상 판정을 전달하지 않는다. 이름 지정 호출이 없는 환경은 아래 실행 방법을 쓴다.
- 반환된 판정과 근거를 work/status.md의 진행 기록에 남긴다. 실패한 요소만 수정하고 바뀐 컷과 영향받은 전환을 재검수한다. 공통 참조를 바꾸면 그 버전을 쓴 떨어진 장면도 확인한다. 판정이 없거나 원본을 열지 못한 항목은 미확인이다.
- 모든 장면과 인접 전환의 현재 버전이 통과하면 `flow-scene-video`에 시나리오·모드·규격, 장면순 콘티 경로와 버전, 참조 대응, 엔딩, 검수 기록 위치를 넘긴다.

**검수 호출** · 이름 지정 하위 에이전트 도구가 있으면 `storyboard_reviewer`를 선택한다. 해당 도구가 없으면 Python 3.11 이상에서 이 스킬의 `scripts/review.py`를 실행하고 검수 의뢰를 표준입력으로 전달한다. 현재 사용자가 인증한 Codex CLI와 같은 역할 파일을 적용한 별도 읽기 전용 실행이다. 호출 오류는 표준 오류와 종료 코드를 7단계에 기록하고 복구한다. 결과가 없으면 판정은 미확인이다. Python, CLI, 인증, 네트워크 또는 실행 권한의 문제를 구분하고 필요한 조작을 안내한다. 플러그인 설치 후 새 채팅에서 담당 스킬을 확인한다.

프로젝트 루트에서 검수 의뢰를 UTF-8 텍스트 파일로 준비해 실행한다. 명령은 예시이며 결과와 실행 오류를 각각 보존한다.

```sh
python3 .production/review.py < review-request.txt > review-result.txt 2> review-error.txt
```

Windows PowerShell에서는 먼저 `$OutputEncoding = [Text.UTF8Encoding]::new($false)`를 실행하고 `Get-Content -Raw -Encoding UTF8 review-request.txt | python .production/review.py`를 사용한다. 각각 Python 3.11 이상을 가리키는지 먼저 확인하고, 다른 이름으로 설치됐다면 그 실행 경로를 사용한다. 인증은 해당 사용자가 Codex CLI에서 직접 수행한다. 오류 때문에 권한이 필요하면 원인과 실행 범위를 확인한다.
