# Flow와 HyperFrames AI 영상 제작 15단계 작업지시서

Google Flow와 gflow로 장면을 만들고 HyperFrames Desktop에서 편집한다. 작업의 마지막 산출물은 **사용자가 HyperFrames에서 재생할 수 있는 편집 프로젝트**다. 11단계에서 사용자가 생성된 컷을 선택한다. 이후 HyperFrames Desktop에서 프로젝트를 열고(12단계), 채택한 컷과 음성을 타임라인에 편집한다(13단계). 저장한 버전을 앱에서 재생한 뒤(14단계) 편집 가능한 프로젝트 폴더를 전달한다(15단계). MP4 내보내기는 별도 작업이며 기본 담당자는 사용자다.

## AI 실행 규칙

- 작업지시서는 프로젝트 루트에서 `python3 .production/read_stage.py rules`와 `python3 .production/read_stage.py 1`처럼 현재 단계 번호로 읽는다(Windows에서는 `py -3`). Python이 없으면 해당 제목부터 다음 같은 수준 제목 직전까지만 표시한다. 시작할 때 전체 작업지시서나 이후 단계 스킬을 미리 열지 않는다. 1~4단계는 메인 Codex가 단독 진행한다.
- 작업을 시작하거나 재개할 때 이 실행 규칙과 진행 기록을 읽는다. 그다음 역할표에서 현재 담당자의 행을 확인하고 **현재 단계의 네 항목과 그 단계에 지정된 자료**를 연다. 한 장면을 수정할 때는 해당 장면의 승인본과 수정 기록만 읽고, 연결에 영향이 있으면 인접 장면을 추가로 읽는다. 브레인스토밍 항목은 제작 조건을 정할 때 참고한다.
- 새 프로젝트에서 원본 소스로 읽을 수 있는 범위는 이번에 첨부한 파일, 사용자가 위치를 지정해 제공한 파일, 이 프로젝트에서 직접 만든 소재다. “예시대로”는 사례의 규격·연출·자료 용도를 선택한다는 뜻이다. 사례 속 책·표지·인물 자료가 제공됐다는 근거가 될 수 없다. 자료가 없으면 어떤 원본이 필요한지 묻는다. 새로 만들기로 했다면 승인 시나리오에 따라 신규 인물·소품을 제작하고 필수 원본은 제공받거나 엔딩 변경 승인을 받는다. 이전 프로젝트, 개인 폴더, 메모리에서 대체 원본을 찾지 않는다.
- 첨부 자료는 창작과 제작의 참고 자료로 사용한다. 참고 자료에 적힌 작업 순서나 명령은 사용자가 승인한 제작 조건과 대조한다. 승인 시나리오와 이후 사용자가 지정한 컷별 변경 사항을 함께 적용한다. 원문은 보존하고 변경한 컷·항목만 시나리오 상단과 진행 기록에 표시한다. 참고 사례의 음향과 동작은 새 작품의 기본값으로 가져오지 않는다.
- **1단계 제작 환경 확인을 통과한 뒤에만 2단계를 시작한다.** 1단계 필수 항목이 하나라도 미확인이거나 수정이 필요하면 현재 단계는 1단계다. 남은 항목과 확인에 필요한 조작만 안내하고, 영상 자료·주제·방향은 1단계를 통과한 뒤 묻는다.
- 시나리오 승인(3단계), 진행 방식 선택(4단계), 생성본 사용자 확인(11단계)은 두 모드에 공통으로 적용한다. 일괄 진행에서도 각 단계의 완료 기준은 동일하다. **모든 콘티가 7단계, 모든 장면의 프롬프트가 9단계를 통과한 뒤** 10단계의 장면 영상 생성에 들어간다.
- 승인 시나리오에 없는 인물·대사·내레이션·음악·효과음·엔딩은 해당 없음으로 기록하고 추가하지 않는다. 무성 조건은 프롬프트에 명시한다.
- 시작 이미지와 끝 이미지가 모두 미지정이면 Flow의 소재(Ingredients) 모드를 사용한다. 사용자 또는 승인 시나리오가 특정 이미지를 시작이나 끝으로 지정한 컷만 프레임(Frames) 모드로 만들고, 지정된 파일만 해당 위치에 넣는다.
- 생성용 프롬프트는 한국어 검토본과 영어 제출본을 함께 보관한다. Flow에는 영어 제출본을 사용하고 발화 원문은 승인된 언어로 유지한다. 두 언어판의 장면 번호와 버전을 일치시킨다.
- 산출물은 프로젝트의 .production/layout.md에 지정한 경로에 저장한다. 산출물마다 장면 번호와 버전을 기록한다. 진행 기록에는 `현재 단계 | 장면 또는 프로젝트 버전 | 파일 위치 | 판정 | 남은 문제 | 다음 작업 또는 대기 상태`를 남긴다. 사용자 승인은 무엇을 어느 버전으로 승인했는지 적는다. 세션을 다시 열면 이 기록에서 이어간다.
- 장면별 정보는 한 줄씩 관리한다. 8단계에서 작성하고, 10~14단계에서 실측과 판정을 같은 줄에 갱신한다.

```text
장면 | 콘티·프롬프트 버전 | 영상·오디오 출처 | 원본 길이·사용 구간 | 마지막 발화 | 오디오 페이드·다음 장면 시작 | 판정·근거
```

원본의 시간과 HyperFrames 타임라인 시간을 구분한다. 발화 위치는 목표값, 전사 추정값, 직접 들은 결과를 구분해 적는다. 검수 근거에는 확인한 사람, 버전, 구간과 확인 방법을 남긴다.

### 제작 전 검수와 생성 후 사용자 확인

1. 콘티는 7단계, 한·영 프롬프트는 9단계 기준으로 검수한다. 수정이 필요한 자료는 해당 단계에서 수정하고 다시 확인한다.
2. 생성 후 Codex는 파일 저장과 링크·재생 가능 여부 등 전달에 필요한 기술 상태를 확인한다. 연기·움직임·립싱크·음성 등 영상의 품질은 사용자가 직접 판단한다. 프레임 분석, 자동 전사, 품질 보고서 작성, 임의 보정이나 재생성은 기본 절차에서 제외한다.
3. 영상과 편집본은 각각 11단계와 15단계에서 사용자에게 전달한다. 사용자가 직접 지정한 확인 시점이나 이미 승인한 후속 범위가 있으면 그 지시를 따른다. 11단계의 사용자 선택을 기록한 뒤 12~14단계의 HyperFrames 편집과 앱 재생을 진행한다. 15단계에서는 편집 가능한 프로젝트를 전달하고 마친다.

## 01. 제작 도구 설치 여부 확인

- **읽을 자료** · 이번 제작에 사용할 컴퓨터의 설치 정보.
- **할 일** · gflow는 Mac의 `command -v gflow` 또는 Windows의 `Get-Command gflow`로 위치를 찾는다. HyperFrames Desktop은 응용 프로그램 폴더 또는 설치된 앱 목록에서 확인한다. 직접 조회할 수 없으면 해당 사용자의 설치 확인으로 갈음한다. 검색 경로에 없다는 사실만으로 미설치를 단정하지 않는다.
- **미설치 시** · 대상 컴퓨터의 OS와 CPU 아키텍처를 확인한다. 빠진 도구만 [gflow 설치 안내](https://github.com/ffroliva/gflow-cli#60-second-quick-start) 또는 [HyperFrames Desktop 설치 안내](https://github.com/heygen-com/hyperframes/blob/main/docs/studio-app/index.mdx)의 지원 방식으로 설치한다. 프로젝트 지정 배포처가 있으면 그 설치 방법을 따른다. 관리자 승인이나 설치 창 조작이 필요하면 해당 조작만 사용자에게 요청한다. 설치가 끝나면 같은 방법으로 설치 위치 또는 앱 목록을 다시 확인한다.
- **산출물** · 각 도구의 설치 여부와 확인 근거. 설치를 시도했다면 대상 환경과 재확인 결과도 남긴다.
- **완료 기준** · 두 도구의 설치가 확인되면 곧바로 2단계를 시작한다. 확인할 수 없는 항목은 그 설치 여부만 묻는다. 설치 실패 또는 미지원 환경에서는 해당 도구와 원인을 기록하고 1단계에 머문다.

Flow 로그인·생성 화면은 Flow를 처음 사용할 때 확인한다. HyperFrames 실행·제어와 미리보기는 12단계에서 확인한다.

## 02. 영상 소스와 제작 방향 확인

- **읽을 자료** · 1단계 통과 기록, 사용자 요청과 제공된 문서, 이미지, 영상, 오디오 목록. 1단계 통과 기록이 없으면 1단계 확인부터 이어간다.
- **할 일** · 2단계를 시작하거나 재개할 때 작업지시서의 2단계를 다시 읽는다. 이미 첨부한 자료를 확인하고, 답이 빠진 질문만 골라 **아래 질문과 그에 해당하는 이전 사례를 문구 그대로 한 쌍으로** 보여준다. 채팅에서는 원래 번호와 질문 제목을 소제목으로 쓰고, 설명은 다음 문단에, 이전 사례는 그 아래 인용문에 표시한다. 사례가 길면 문장 사이에서 인용문을 두 문단으로 나눈다. 전송 직전에 질문과 사례의 문구·수치를 원문과 대조하고, 달라졌거나 빠진 부분이 있으면 해당 질문과 사례 전체를 원문으로 교체한다. 사용자는 정해진 항목에만 답하거나 “예시대로”, “이 부분만 변경”, “미정”이라고 답할 수 있다. 미정인 제작 조건은 3단계 시나리오 제안에 선택안으로 담는다. 확인한 원고의 핵심 문장과 새로 구성할 이야기를 구분해 적는다.

### 1. 어떤 자료를 어디에 쓸까요?

영상에 그대로 넣을 자료와 내용이나 분위기만 참고할 자료를 알려주세요.

> **이전 사례** · 책의 보도자료는 책 정보 확인에, 유튜브 스크립트는 이야기 기획에 썼습니다. 책 표지는 영상 마지막에 원본 그대로 넣었습니다.

### 2. 누구에게 보여주고 어떤 반응을 바랄까요?

영상의 주제, 보여줄 사람, 올릴 곳, 보고 난 뒤 기대하는 반응을 알려주세요.

> **이전 사례** · 수능 전날 학부모에게 보여줄 유튜브 쇼츠였습니다. 엄마와 딸의 이야기를 보고 마음이 조금 편해지고, 소개한 책을 찾아보길 바랐습니다.

### 3. 어떤 길이와 화면으로 만들까요?

길이와 화면비를 먼저 골라주세요. 원하는 그림체나 내레이션·음악·자막 조건이 있다면 함께 알려주세요.

> **이전 사례 규격** · 30초, 세로 9:16, 720×1280, 24fps. OmniFlash 1.2로 지브리 그림체의 영상을 만들고, 화면 밖 내레이션은 50대 중년 아나운서처럼 안정적인 목소리로 연출했습니다. 잔잔한 피아노를 넣고, 자막 없이 마지막 3초에 책 표지를 보여줬습니다.
>
> 가로 영상이라면 **16:9 가로**처럼 원하는 항목만 바꿔 답할 수 있습니다.

- **산출물** · 제작 브리프와 소스 목록. 파일 위치, 용도, 필수 문구와 누락 자료를 기록한다.
- **완료 기준** · 영상의 목적과 방향, 필수 소스 및 제작 규격이 정리되어 이를 바탕으로 시나리오를 제안할 수 있다. 자료가 부족하면 어떤 결정을 막는지 설명할 수 있다.

## 03. 시나리오 제안 및 승인

- **읽을 자료** · 2단계 제작 브리프와 시나리오에 직접 쓰는 원고·레퍼런스.
- **할 일** · 시나리오 제목과 버전, 이야기의 시간대, 주요 소품을 정해 보여준다. 장면 순서와 길이, 장소, 인물, 행동, 화면 밖 내레이션과 감정 변화, 엔딩을 제안한다. 행동과 소품이 이야기의 시간대에 모순 없이 들어가는지 확인하고, 대사를 자연스러운 속도로 읽을 시간을 가늠한다. ‘이전 시나리오’로 되돌릴 때는 대화에서 해당 제목·버전을 찾고, 여러 후보가 남으면 확인받는다.
- **산출물** · 제목·버전·시간대·핵심 소품과 장면별 시간·행동·내레이션이 포함된 승인 시나리오.
- **완료 기준** · 어느 제목과 버전을 사용자가 승인했는지 확인된다. 장면과 소품은 설정한 시간대에 맞고, 장면 및 엔딩 길이의 합계는 목표 재생 시간과 일치한다.

## 04. 순차·일괄 진행 방식 선택

- **읽을 자료** · 승인 시나리오, 사용자가 원하는 확인 빈도와 참여 방식.
- **할 일** · 두 요청 예시를 보여주고 어느 방식으로 갈지 확인한다.
  - **순차 진행** · “제작 중에는 단계별 산출물을 보여주고 내 확인을 받아줘. 마지막에는 편집 프로젝트를 전달해줘.”
  - **일괄 진행** · “승인된 시나리오대로 콘티와 프롬프트를 준비하고 장면을 일괄 생성해 보여줘. 내가 선택한 컷으로 HyperFrames 미리보기를 만들어줘.”
- **산출물** · 선택한 진행 방식과 사용자가 지정한 중간 확인 지점.
- **완료 기준** · 진행 방식을 확인했고, 편집 프로젝트 전달로 완료한다는 조건을 기록했다. 일괄 진행 중에도 로그인 등 사용자만 해결할 수 있는 문제나 승인 범위 변경은 해당 지점에서 확인한다.

## 05. 캐릭터시트 제작

- **읽을 자료** · 승인 시나리오의 등장인물과 해당 인물의 외형·의상·스타일 레퍼런스.
- **할 일** · 콘티 생성 전에 아래 순서로 개별 참조를 준비한다.
  1. **인물마다 캐릭터시트 한 장**을 만든다. 한 장 안에 **같은 인물의 정면·45도·측면 등 최소 세 가지 각도**를 담는다. 모든 각도에서 얼굴, 헤어, 체형, 의상을 일치시키고 서로 가리지 않게 배치한다. 인물별 시트는 각각 저장해 Flow에 개별 참조로 올린다.
  2. 책 표지나 제품 사진처럼 제공받은 소품 원본은 소품별로 Flow에 올린다. 파일 이름과 해당 소품을 기록한다.
  3. 원본이 없거나 장면에 맞는 각도·그림체가 필요한 반복 소품은 **한 이미지에 소품 하나씩** 별도로 만든다. 원본이 있으면 이를 참조해 제작하고, 제작 이미지는 원본과 구분해 저장하고 올린다. 소품의 모양·색·크기·구별되는 특징과 장면별 상태 변화를 적는다.
- **산출물** · 인물별 캐릭터시트, 반복 소품별 원본·제작 참조, 장면별 등장·변경 조건과 Flow 참조 목록.
- **완료 기준** · 콘티에 필요한 인물과 소품을 각각 Flow에서 선택할 수 있다. 인물별 시트마다 같은 인물이 최소 세 가지 각도로 선명하게 보이고 외형·의상이 일치한다. 각 제작 소품 참조에는 소품 하나가 또렷하게 보인다. 반복 제품·공간의 기준도 장면에 맞게 준비한다. 반복해 참조할 대상이 없는 영상은 5단계를 해당 없음으로 기록한다.

## 06. 전체 장면의 콘티 이미지 제작

- **읽을 자료** · 승인 시나리오, 그 장면에 등장하는 인물별 캐릭터시트와 소품별 참조, 배경 기준 이미지. 후속 장면부터는 확정한 첫 장면과 직전 장면의 콘티도 함께 본다.
- **할 일** · 시나리오 순서대로 만든다. 첫 장면을 먼저 제작하고 시나리오와 7단계의 개별 이미지 기준을 확인해 기준 콘티로 확정한다. 다음 장면은 첫 장면과 직전 확정 콘티를 보며 만드는 장면의 행동·감정이 앞 장면에서 어떻게 이어지는지 확인한다. 같은 인물과 공간이면 외형·의상·조명과 배경의 특징을 이어가고, 반복 소품은 기준 이미지의 모양·색을 유지한다. 누가 소품을 들고 있는지, 어느 위치에 놓였는지, 열고 닫은 상태가 어떻게 바뀌는지는 시나리오에 맞춘다. 장면에 맞는 각도를 인물별 시트에서 고르고, 여러 각도가 함께 생성되면 필요한 각도만 단일 이미지로 참조한다. 장면마다 필요한 구도·시선·자세로 구성하고, 움직임이 한 장으로 전달되기 어려우면 연결 콘티를 추가한다. 이미지를 만들 때 컷별로 파일의 용도(소재·시작 이미지·끝 이미지·편집용 원본)를 기록한다. 시작·끝 지정에는 해당 요청이나 시나리오 구간을 적는다. 콘티 채택, 첫 장면이라는 순서, 편집용 엔딩 표지는 프레임 지정의 근거가 되지 않는다. 엔딩에 지정한 원본은 파일과 표시 시간을 콘티 목록에 적는다.
- **산출물** · 첫 장면 기준 콘티, 전체 장면의 콘티 이미지와 장면별 시나리오·사용한 참조 대응 목록.
- **완료 기준** · 각 콘티가 승인한 화면비와 시나리오의 행동·구도를 따르며, 어떤 참조를 써서 앞 장면과 연결했는지 장면별로 확인할 수 있다.

## 07. 전체 콘티 이미지 검수

- **읽을 자료** · 승인 화면비, 6단계 콘티 목록과 원본(첫 검수는 전체, 재검수는 아래 역할표의 변경 범위), 첫 장면 기준 콘티, 대응하는 시나리오 구간, 캐릭터시트와 반복 소품·배경의 기준 이미지.
- **할 일** · 7단계 검수 에이전트가 콘티 원본을 한 장씩 열어 아래 기준을 판정하고 인접 장면의 연결도 확인한다. 에이전트는 판정과 근거를 반환하고, 콘티 제작 스킬은 기록·수정·재검수 요청을 맡는다. 분할이나 접합이 반복되면 참조에 사용한 이미지에도 같은 흔적이나 다중 패널이 있는지 확인하고, 접합 없는 단일 프레임을 참조로 바꿔 다시 검수한다. 수정이 연결에 영향을 미치면 앞뒤 장면도 다시 확인한다.
- **산출물** · 채택 콘티와 장면별 버전·검수 항목·판정. 수정한 장면은 수정 전후의 차이와 재검수 결과도 기록한다.
- **완료 기준** · 승인 시나리오의 장면 목록과 대조해 누락이 없고, 각 장면과 모든 인접 전환이 현재 콘티 버전으로 통과했으며, 영상 프롬프트에 쓸 콘티 버전이 확정됐다. `수정 필요`나 `미확인`이 남은 장면은 7단계에서 수정·재검수를 이어간다.

  - 각 콘티는 승인한 화면비의 한 장면이다. 한 화면 안에 의도하지 않은 분할이나 이음선, 중복된 배경이 없다.
  - 시나리오가 지정한 인물·장소·핵심 행동과 표정이 화면에서 읽힌다.
  - 콘티를 순서대로 보면 직전 장면의 행동이나 감정이 다음 장면에서 어떻게 이어지는지 읽힌다. 시나리오에 정한 장소·시간·구도 변화도 화면에서 드러난다.
  - 첫 장면과 기준 이미지를 바탕으로 인물의 외형·의상, 반복 소품의 모양·색·크기, 화면 방향과 배경이 이어지는지 확인한다. 소품의 위치, 소품을 든 인물, 소품의 상태 변화는 장면 순서와 시나리오에 맞는다.
  - 엔딩에 지정한 원본 소재가 있으면 콘티 목록에서 파일과 표시 시간을 확인할 수 있다.

## 08. 장면별 영상·내레이션·효과음 프롬프트 작성

- **읽을 자료** · 해당 장면과 앞뒤 장면의 채택 콘티, 승인 시나리오, 인물·소품별 기준 이미지, [Flow 영상 생성 도움말](https://support.google.com/flow/answer/16353334?hl=en), [Flow 모델별 지원 기능](https://support.google.com/flow/answer/16352836?hl=en), [Google 영상 프롬프트 가이드](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/video/video-gen-prompt-guide).
- **할 일** · 승인 시나리오에 해당하는 항목만 장면별로 분석해 프롬프트와 참조 계획에 적는다. 지원 모델·참조 모드·첨부 가능 여부를 확인할 수 없으면 초안과 미확인 항목을 기록하고 8단계에서 대기한다.
  - **내레이션 제작 방식** · 승인된 내레이션은 기본적으로 장면 영상과 함께 생성한다. 화면 동작, 화면 밖 화자의 목소리·연기, 승인 대사 원문을 Flow에 한 번에 제출하는 같은 프롬프트에 쓴다. 사용자가 별도 녹음이나 제공 음원을 지정한 경우에만 해당 방식을 기록해 적용한다. 음성 참조는 특정 음색을 재현할 때 쓰는 선택 입력이다. 음성 참조를 첨부할 수 없어도 동시 발화를 지원하면 같은 화자 설명으로 진행한다. 선택한 모델·모드의 동시 발화 지원이 불확실하면 그 기능을 확인하고, 미지원이면 동시 생성이 가능한 설정을 먼저 검토한다. 제작 방식을 변경해야 할 때만 사용자에게 확인한다.
  - **화면과 연결** · 콘티 원본에서 인물의 시선·손·자세, 소품 위치, 구도·조명·배경을 확인한다. 프롬프트에는 시나리오에 맞는 시작 상태, 핵심 행동·감정과 카메라 움직임, 끝 상태를 적는다. 소재 모드에서는 한·영 프롬프트에 @파일명과 그 소재의 역할을 함께 적는다. Flow 제출 시 입력란에서 @를 입력하고 목록에서 해당 프로젝트 소재를 선택한다. 생성 직전에 본문 안의 소재 태그 이름·개수·역할을 제출본과 대조한다. 채택 콘티가 있는 각 컷은 콘티 파일명을 첨부 목록, 한·영 본문의 @태그, 실제 Flow 본문의 연결 태그와 차례로 대조한다. 시작·끝 이미지 지정이 없으면 콘티도 소재로 연결한다. 지정 소재를 모두 연결할 수 없는 경우에는 누락한 상태로 전송하지 않고 해당 컷의 구성을 확인한다. 카메라는 고정을 기본으로 한다. 시나리오에 꼭 필요한 동작은 시작 위치를 가까이 잡아 이동 거리와 회전 폭을 줄이고, 여러 동작은 차례로 마친다. 최신 승인 연출이 요구하는 움직임만 두 언어판에 남긴다. 이 작품처럼 사용자가 표정 연기만 지정한 컷은 콘티의 자세·카메라·인물 위치와 소품 배치를 유지한다. 감정은 눈빛·눈썹의 작은 변화로 지정한다. 입술은 붙어 있고 턱은 정지한다. 내레이션의 질문·강세·쉼이나 책 제목을 화면 인물의 대사 또는 입 모양으로 옮기지 않는다. 이전 시나리오에 걷기·착석·담요 펼치기가 있어도 최신 사용자 수정이 해당 동작을 제외하면 한·영 제출문 양쪽에서 삭제한다. 장면마다 첫 자세, 허용되는 변화, 끝까지 고정할 대상을 구체적으로 쓴다. 앞 컷이 끝나는 시선·동작·소품 위치를 다음 컷이 어떻게 받아오는지 적고, 의도된 구도·시간·장소 변화도 표시한다.
  - **무언 연기 공통 지시** · 인물이 등장하는 각 컷의 화면 지시에 “화면 속 인물은 끝까지 말하지 않는다. 입술은 자연스럽게 다물고 말하는 듯한 입술·턱 움직임과 립싱크 없이, 시선·표정·손동작·호흡으로 반응한다”를 넣는다. 오디오 지시에는 승인된 문장을 화면 밖 내레이터에게만 지정한다.
  - **Flow 참조** · 인물 외형·의상과 소품을 유지할 때는 해당 개별 자산을 소재(Ingredients)로 선택하고 각각의 역할을 프롬프트에 적는다. 시트에서 장면 구도에 맞는 각도를 골라 인물의 외형을 확인한다. 여러 각도가 한 컷에 함께 생성되면 해당 각도의 단일 이미지로 참조를 바꾼다. 시작 이미지와 끝 이미지가 모두 미지정이면 Flow의 소재(Ingredients) 모드를 사용한다. 사용자 또는 승인 시나리오가 특정 이미지를 시작이나 끝으로 지정한 컷만 프레임(Frames) 모드로 만들고, 지정된 파일만 해당 위치에 넣는다. 끝 이미지만 지정했는데 해당 슬롯 단독 사용이 불가능하면 지원 설정을 확인하고 제약을 기록한다. 임의의 시작 이미지를 추가하지 않는다. 채택 콘티와 앞뒤 컷은 연결 기준으로 대조하고, 실제 생성에는 선택한 모드에서 지원하는 참조를 첨부한다. [Flow 클립·프레임 저장 안내](https://support.google.com/flow/answer/16935718?hl=en)
  - **효과음·환경음·배경음악** · 사용자가 허용한 음향에만 다음 예시를 적용한다. 화면 밖 내레이션만 지정하면 한·영 생성문에는 발화를 유지하고 배경음악·효과음·환경음 제외를 적는다. 효과음은 화면에 보이는 동작과 시점을 맞춘다. 예를 들어 물병이 책상에 닿을 때 작게 한 번 울린다. 환경음은 같은 공간의 소리가 컷 사이에 어떻게 이어지는지 적는다. 배경음악은 공통 악기·분위기와 컷 앞뒤에 이어질 구간을 정하고, 내레이션이 분명히 들리도록 크기를 조절할 계획을 적는다.
  - **내레이션** · 영상 주제와 인물의 감정에 맞는 화자, 말투, 속도·쉼·강세를 장면별로 적는다. 걱정에서 멈춤, 다정한 변화, 책에 대한 궁금증으로 감정이 이어지게 한다. 승인된 한국어 대사는 제출본에 그대로 넣고 발화 길이를 확인해 마지막 음절이 잘리지 않도록 배치한다. 엔딩 표지 아래로 이어지는 발화는 승인한 음성 종료 시각을 따른다. 음성 참조를 쓰기로 한 경우 지원되는 모드에서 같은 참조를 적용한다. 원본 생성 길이와 편집에 쓸 길이를 각각 적는다.
  - **내레이션 중심 작품 예시** · 승인 모델이 Omni 1.2 Flash이면 제출 화면에서 같은 모델을 선택한다. 50대 여성 화자가 지정된 작품은 안정적인 중저음과 장면별 감정을 영어 제출문에 담고 실제 발화는 승인된 한국어 원문으로 유지한다. 화면 속 인물은 입을 다물고 표정으로만 연기한다. 내레이션 전용 컷은 배경음악·환경음·효과음을 생성하지 않는다.
  - **한국어판과 영어판** · 같은 버전의 한국어 검토본과 영어 제출본을 전문으로 작성한다. Flow에는 영어 제출본을 넣고 실제 발화는 승인된 언어의 대사 원문을 그대로 둔다. 시나리오의 각 감정을 영어 제출본 안에서 호흡·쉼·강세로 구체화하고 같은 화자의 음색을 유지한다. 현재 프로젝트에서 지정한 모델명·버전을 제출 화면과 대조한다.
- **산출물** · 장면별 콘티·참조 자산과 각각의 역할, 한국어 검토본과 영어 제출본 전문과 장면별 통과 기준, 영상·음성 생성 방식, 앞뒤 컷 연결과 타이밍 기록.
- **완료 기준** · 각 장면의 시작·끝 상태와 다음 컷으로 이어질 행동·소리가 명확하다. 해당하는 화면·음성 참조 계획을 선택한 Flow 모드에서 실행할 수 있고, 해당하는 효과음과 승인 대사가 자연스럽게 들어갈 여유가 있다.

## 09. 전체 장면 프롬프트 검수

- **읽을 자료** · 8단계 프롬프트와 최신 승인 시나리오, 채택 콘티, 공통 무언 연기 조건.
- **할 일** · 프롬프트를 읽기 전에 마지막으로 승인된 시나리오의 버전과 해당 구간을 표시하고, 그 구간에서 반드시 보여야 할 행동·감정 변화, 들려야 할 대사, 전환·엔딩 조건을 관찰 가능한 통과 기준으로 적는다. 이후 승인된 콘티나 사용자 변경 사항은 출처를 구분한다. 이미지 용도 기록과 두 언어판의 참조 지시가 선택한 소재·프레임 모드에 맞는지 확인한다. 한국어판과 영어판 각각을 같은 기준으로 판정하고 근거를 남긴다. 시나리오 요구가 빠졌거나 양쪽 의미가 다르면 해당 장면을 수정하고 재검수한다. 생성 후 사용자가 확인할 항목은 별도로 표시한다. 동시 생성 장면은 Flow에 실제로 보낼 입력만 따로 읽고, 화면 밖 화자와 승인 대사 원문이 모두 들어 있는지 확인한다. 대사가 제출문 밖 메모에만 있거나 전체 무음 지시와 충돌하면 8단계에서 고친다. 인물이 등장하는 모든 프롬프트의 화면 지시에 8단계의 무언 연기 문구가 있고, 오디오 지시에서 승인 대사 전부가 화면 밖 내레이터에게만 지정됐는지 확인한다. 화면 속 인물의 행동이 말하거나 속삭이거나 답하는 것으로 적혀 있으면 시나리오에 맞는 시선·표정·손동작으로 바꾼다. 내레이션 감정이 장면별 목표에 맞는지, 발화 끝이 승인된 구간에 들어가는지 확인한다. 화면 전환 뒤까지 이어지는 내레이션은 다음 화면에서 마지막 음절까지 들리도록 지정한다.
- **산출물** · 장면별 시나리오 근거·통과 기준·한국어판과 영어판의 판정·수정 사항, 채택 프롬프트 버전.
- **완료 기준** · 모든 프롬프트에서 콘티·시나리오·승인 대사·타이밍이 서로 일치한다. 인물·소품 참조의 역할과 앞 컷 끝에서 다음 컷 시작으로 이어지는 동작이 명확하다. 무언 연기, 화면 밖 목소리와 장면별 감정, 허용한 음향의 시점과 연결 또는 사용자가 지정한 음향 제외 조건이 양쪽에 명시돼 있다.

## 10. 요청한 장면의 영상 및 오디오 제작

- **읽을 자료** · 전 장면의 9단계 통과 기록. 각 생성에 해당 장면의 채택 프롬프트, 참조 이미지, 생성 설정을 읽는다.
- **할 일** · Flow에서 승인된 프롬프트로 이번에 요청한 컷만 생성한다. “다음”은 기록된 다음 작업으로 이어간다. “프롬프트 작성”은 문서 작성, “생성”은 지정 컷 제출, “방금 다운받은 걸로 편집”은 선택 파일을 사용한 편집으로 기록한다. 동시 생성 장면은 9단계를 통과한 화면·발화 지시 전문을 같은 영상 요청으로 전송한다. 전송 직전에 모델명·버전, 영어 제출문 전문과 승인 발화 원문, 이미지 용도 기록과 실제 소재·프레임 슬롯을 대조한다. 이전 모델의 테스트는 별도 이력으로 기록한다. 선택한 참조 모드와 모델·길이·화면비, 실제 첨부된 인물·소품·프레임·음성 자산이 장면 계획과 맞는지 확인한다. 재개하거나 응답이 끊겼을 때는 기존 Flow 작업에서 요청 상태와 다운로드 여부를 먼저 확인한다. 완료됐으면 기존 결과를 받는다. 실패를 확인한 요청만 다시 시도한다. 채택한 화면이나 소리 중 재사용할 수 있는 요소를 기록한다.
- **산출물** · 요청한 장면의 영상·오디오 파일, 대응 프롬프트·생성 설정, 요청 상태와 다운로드 위치.
- **완료 기준** · 이번에 요청한 장면 파일을 열어 재생할 수 있고, 계획한 구간을 편집할 수 있는 분량과 필요한 음원이 확보됐다. 무성 조건이면 음원이 필수라는 뜻이 아니다.

## 11. 생성된 장면 사용자 확인

- **읽을 자료** · 이번에 생성한 장면 번호, 버전, 저장된 영상 링크와 이미 받은 사용자 의견.
- **할 일** · 요청받은 컷을 생성·저장하면 해당 영상을 사용자에게 보여준다. 여러 컷을 요청받으면 요청 범위대로 제작한 뒤 한 번에 전달할 수 있다. 사용자가 직접 보고 듣고 사용할 컷, 수정할 컷, 제외할 컷을 정한다.
- **산출물** · 장면별 영상 링크와 사용자 선택. 응답 전에는 `사용자 확인 대기`로 기록한다.
- **완료 기준** · 사용자가 사용할 컷과 후속 작업을 지정했다. Finder에서 파일을 선택해 편집을 지시한 경우 그 파일을 채택으로 기록한다. 이미 받은 선택을 적용하고, 수정 의견이 있는 컷만 새 버전으로 만들어 다시 전달한다.

## 12. HyperFrames Desktop에서 편집 프로젝트 열기

- **읽을 자료** · HyperFrames 실행 상태, 현재 Codex 컴퓨터 제어 가능 여부, 대상 프로젝트와 편집 사본 위치.
- **할 일** · 현재 채팅에 연결된 컴퓨터 제어 도구로 HyperFrames 창을 열거나 안전한 화면 조작을 수행해 응답을 확인한다. 운영체제가 요청하는 권한을 확인하고, 앱의 기존 작업은 보존한다. 기존 사본은 앱의 **File → Open Folder…** 또는 **Import projects → 폴더 선택**에서 `index.html`, `hyperframes.json`, `assets/`가 들어 있는 프로젝트 폴더 전체를 가져온다. 새 편집은 **Edit my own footage** 또는 설치 버전의 영상 가져오기 기능으로 채택 파일을 불러온다. 열린 프로젝트와 편집할 버전이 일치하는지 확인한다. 요청한 제어 경로를 쓸 수 없으면 사용자에게 필요한 조작을 안내한다. 작업 기록에 Desktop 직접 제어, 사용자 조작, CLI 이용 중 실제 사용한 방식을 적는다.
- **산출물** · 앱 제어 가능 여부와 편집에 사용할 프로젝트 위치.
- **완료 기준** · 편집할 프로젝트와 앱을 식별했고, 선택한 방식으로 프로젝트 열기와 미리보기 재생을 확인했다. 제어 제한이 있으면 사용자가 맡을 조작이 정해져 있다.

## 13. HyperFrames 타임라인 배치 및 전환 적용

- **읽을 자료** · 장면별 채택 파일과 승인 시나리오, 타임라인 규격, 12단계에서 확인한 프로젝트.
- **할 일** · 선택 파일은 생성 ID·파일명으로 컷과 대응시키고 새 편집 사본의 소재로 복사한다. 타임라인의 실제 영상 소스가 그 파일인지 확인한다. 같은 생성 ID의 보정본이 있으면 원본과 구별하고, 음성을 이전 편집에서 이어 썼다면 그 출처와 사용 구간도 기록한다. 채택한 다른 컷과 제외한 컷의 결정은 유지한다. HyperFrames 타임라인에 채택 컷을 승인 순서로 놓고 각 컷의 시작점과 끝점을 맞춘다. 화면 밖 내레이션은 생성본에 들어 있는 음성을 사용하며, 엔딩 이미지 아래까지 이어지는 발화는 마지막 음절까지 들리도록 음성 구간을 배치한다. 음악·효과음·환경음은 승인된 경우에만 배치한다. 같은 음악을 이어가는 장면은 가능하면 한 트랙으로 연결하고, 환경음은 공간이 이어지는 구간에 걸쳐 맞춘다. 약 1초 페이드인·아웃을 기본으로 두고, 장면 기록의 마지막 발화와 오디오 페이드 시작점을 비교한다. 겹치면 실제 미리보기를 기준으로 영상·음성 페이드를 개별 조정한다. 교체 요청에는 영상만, 오디오만, 둘 다 중 어느 범위인지와 각 출처 버전을 확인한다. 예를 들어 `01 영상·오디오 v03 / 02~04 v06`처럼 기록하고 중복 오디오가 없는지 확인한다.
- **산출물** · 저장된 편집 프로젝트와 장면별 사용 구간·전환 시점·영상과 오디오의 출처 버전.
- **완료 기준** · 장면 순서, 전체 길이, 엔딩 시간 및 화면비가 승인 내용과 일치한다. 타임라인에 사용자 지정 영상·음성 파일과 엔딩이 연결돼 있다.

## 14. HyperFrames Desktop에서 저장한 타임라인 재생

- **읽을 자료** · 편집 프로젝트와 사용자가 선택한 장면 버전, 편집 지시.
- **할 일** · 편집한 프로젝트를 저장하고 HyperFrames Desktop에서 같은 버전의 타임라인을 재생한다. 장면 전환에서 다음 컷이 표시되는지, 지정한 음성 트랙이 재생되는지, 엔딩과 종료 시각이 맞는지 확인한다. 별도 HTML을 제공하면 그 링크도 확인한다.
- **산출물** · 사용자에게 전달할 미리보기 링크, 버전, 전체 길이와 이번에 변경한 구간.
- **완료 기준** · 앱에서 확인한 버전과 타임코드 범위를 기록한다. 버튼 클릭, 총 길이 표시, 파형만으로 전체 재생이나 청취를 완료 처리하지 않는다. 재생이 중단되면 확인된 마지막 지점과 남은 구간을 적는다. 끝까지 재생되면 15단계로 간다. 파일이나 별도 HTML만 확인했다면 Desktop 재생은 미확인으로 기록한다.

## 15. HyperFrames 편집 프로젝트 전달

- **읽을 자료** · 14단계에서 준비한 HyperFrames 프로젝트와 미리보기 링크, 버전, 전체 길이.
- **할 일** · HyperFrames에서 다시 열어 수정할 수 있는 프로젝트 폴더 전체를 기본 결과물로 전달한다. 함께 제공하는 미리보기 링크에는 용도를 표시하고 `편집 프로젝트 전달 완료`로 기록한다.
- **산출물** · 사용자에게 전달한 편집 프로젝트와 해당 버전의 미리보기.
- **완료 기준** · 전달이 끝나면 순차·일괄 모두 제작을 마친다. 이후 수정 요청이 오면 지정 구간을 반영해 새 버전을 전달한다.

재사용이 필요하면 편집 프로젝트 폴더 전체를 복제하고 소재를 새 사본에서 교체한다. 복제한 프로젝트의 타임라인과 미리보기를 확인한다.

|---|---|
| **내레이션을 어떻게 확보할까?** | 승인된 내레이션은 기본적으로 장면 영상과 함께 생성한다. 화면 동작, 화면 밖 화자의 목소리·연기, 승인 대사 원문을 Flow에 한 번에 제출하는 같은 프롬프트에 쓴다. 사용자가 별도 녹음이나 제공 음원을 지정한 경우에만 해당 방식을 기록해 적용한다. |
| **사용자가 중간에 어디까지 확인할까?** | 동일한 목소리를 전 장면에 쓰거나 브랜드 발음이 중요하면, 희망할 때 내레이션 톤과 발음 예시를 먼저 확인한다. 시나리오를 승인한 뒤 일괄 진행을 선택했다면 요청받은 컷을 한 번에 전달하고 사용자의 선택을 기록한다. |
| **재생성 비용을 어디서 멈출까?** | 같은 문제가 반복되면 실패 원인에 맞춰 참조·프롬프트·제작 방식 중 원인을 바꿀 수 있는 부분을 수정한다. 비용이나 일정 제약이 있다면 생성 전에 허용 시도 수 또는 크레딧 한도를 정하고 그 범위에서 진행한다. |

## Codex 스킬과 내보내기 승인 설계

### 스킬 3개와 7단계 검수 에이전트

메인 Codex는 1~4단계의 환경 확인, 기획, 사용자 승인과 진행 방식 선택을 맡고, 이후에는 현재 단계에 해당하는 스킬을 불러온다. 공통으로 넘기는 정보는 **현재 단계, 대상 장면, 승인 시나리오 경로·버전, 진행 방식과 사용자가 지정한 중간 확인 지점, 필요한 파일 경로와 버전**이다. 표의 단계 범위는 담당 범위다. 각 스킬은 work/status.md의 진행 기록의 최신 상태와 현재 단계에 필요한 자료만 연다. 메인 Codex는 단계별 완료 근거와 해당 단계에 필요한 사용자 확인을 대조한 뒤 다음 단계로 넘긴다. 실패 기록은 해당 증상을 조사할 때 찾는다.

| 역할 | 읽을 자료 | 넘길 결과 |
|---|---|---|
| **콘티 제작 스킬 · 5~7단계** | 현재 단계 지시, 승인 시나리오의 장면 순서·장소·행동·감정과 제작 규격, 해당 인물·소품·배경 참조. 후속 장면은 첫 확정 콘티와 직전 확정 콘티를 함께 본다. | 검수 에이전트에 승인 화면비와 시나리오의 해당 구간, 장면 순서대로 콘티 파일과 버전, 각 장면에 사용한 기준 이미지와 버전, 엔딩 원본과 표시 시간을 넘긴다. 수정이 필요하면 해당 콘티를 수정하고 에이전트에 다시 검수를 맡긴다. 전체 통과 후 영상 생성 스킬에 채택 콘티·참조 목록과 장면·전환별 최신 통과 기록을 넘긴다. |
| **콘티 검수 에이전트 · 7단계, 읽기 전용** | 7단계 완료 기준, 승인 화면비와 시나리오의 장면 순서·장소·행동·감정, 검수 대상 콘티와 대응하는 인물·소품·배경 참조, 엔딩 원본과 표시 시간. 첫 검수는 전 장면을 순서대로 보고, 재검수는 직전 판정과 참조 대응 목록에서 변경 영향을 받는 장면과 연결을 찾아 본다. | 장면 번호와 콘티 버전(전환은 양쪽 번호·버전), 판정(통과·수정 필요·미확인), 기준과 근거, 수정할 요소를 콘티 제작 스킬에 돌려준다. |
| **영상 생성 스킬 · 8~11단계** | 현재 단계 지시와 필요한 Flow 도움말, 7단계 통과 기록, 현재 장면·앞뒤 연결에 필요한 채택 콘티와 개별 참조, 승인 대사 원문과 연출·음향 조건. 9단계에서 전 장면의 프롬프트를 본다. | 편집 스킬에 장면별 채택 영상·음성 파일과 버전, 배치 순서와 사용 구간, 마지막 발화·음악·효과음 기준, 최종 규격과 엔딩 원본·표시 시간, 11단계의 사용자 선택과 지정한 수정 구간을 넘긴다. 사용자가 지정한 편집 범위를 따른다. 생성 요청 상태는 work/status.md의 진행 기록에 남긴다. |
| **HyperFrames 편집 스킬 · 12~15단계** | 채택 영상·음성, 장면 순서·길이, 엔딩 원본과 편집 지시. | HyperFrames Desktop에서 프로젝트 열기 → 타임라인 편집 → 저장본 재생 → 편집 프로젝트 폴더 전달. 사용한 버전과 전체 길이를 기록한다. |

장면 하나를 고치면 그 장면과 맞닿은 전환을 다시 본다. 첫 기준 콘티나 공통 소품 참조가 바뀌면 6단계의 참조 대응 목록에서 그 버전을 사용한 장면을 찾아, 떨어진 장면까지 변경 영향과 연결을 확인한다. 기준을 충족하는 장면은 판정 근거를 갱신하고 어긋난 장면만 다시 만든다. 프롬프트는 9단계에서 다시 검수하고 수정한 영상은 사용자에게 전달한다. 7단계 판정이 누락됐거나 필수 항목이 미확인이면 그 근거를 확보한 뒤 8단계로 넘어간다. 10단계 생성은 모든 장면의 프롬프트가 9단계를 통과한 뒤 시작한다.

### 프로젝트 전달과 내보내기

1. 편집 프로젝트와 미리보기 전달이 제작의 종료 지점이다.
2. 사용자는 전달받은 프로젝트에서 MP4를 직접 내보낼 수 있다. 사용자가 Codex에 특정 버전의 MP4 저장을 명시적으로 요청하면 그 요청 범위에서 진행한다.
3. **질문 원문 전송을 자동화할 때는 실행기가 문구를 보낸다.** AI는 2단계에서 답이 필요한 질문 번호를 고른다. 채팅 전송을 담당하는 실행기는 선택된 질문과 사례를 이 파일에서 읽어 그대로 보낸다.
